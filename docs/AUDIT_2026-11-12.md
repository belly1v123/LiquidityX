## Findings

[75] **1. _cr divides before it multiplies, so exact-minimum positions fail**

`LoanMarketplace._cr` · Confidence: 75 · seen in 2/2 runs · NEW

**Description**
The ratio helper floors `collateral * price / WAD` before it multiplies by BPS, so a borrower at exactly 150 percent fails every CR check.

**Fix**

```diff
-        return (collateral * price / WAD) * BPS / debtUsd;
+        return collateral * price * BPS / (WAD * debtUsd);
```

[75] **4. minCollateral returns collateral that the CR check rejects**

`LoanMarketplace.minCollateral` · Confidence: 75 · seen in 2/2 runs · NEW

**Description**
A borrower who sends the `minCollateral` quote gets an `InsufficientCollateral` revert, because `_cr` floors the collateral value before it scales by BPS.

**Fix**

```diff
-        return (collateral * price / WAD) * BPS / debtUsd;
+        return collateral * price * BPS / (WAD * debtUsd);
```

[75] **5. A partial fill of a minimum-collateral request fails the CR check**

`LoanMarketplace._takeFromRequest` · Confidence: 75 · seen in 2/2 runs · NEW

**Description**
The pro-rata collateral share rounds down, so a lender's partial fill of a request at the minimum ratio reverts.

**Fix**

```diff
-            share = r.collateral * amount / r.amount;
+            share = Math.mulDiv(r.collateral, amount, r.amount, Math.Rounding.Ceil);
+            if (share > r.collateralRemaining) share = r.collateralRemaining;
```

[75] **6. The oracle treats a future updatedAt as fresh**

`PriceOracleAdapter._isStale` · Confidence: 75 · seen in 2/2 runs · NEW

**Description**
`_isStale` returns false for any `updatedAt` at or after block time, so a feed round stamped in the future keeps an old price valid.

**Fix**

```diff
-        if (updatedAt >= block.timestamp) return false;
+        if (updatedAt > block.timestamp + MAX_FUTURE_SKEW) return true;
+        if (updatedAt >= block.timestamp) return false;
```

## Leads

_Vulnerability trails with concrete code smells where the full exploit path could not be completed in one analysis pass. These are not false positives — they are high-signal leads for manual review. Not scored._

- **Forced BTC breaks the documented balance equality** — `CollateralManager.receive` · seen in 2/2 runs · NEW — A selfdestruct send skips `receive`, so the balance can exceed the tracked totals. Nothing reads the balance.
- **Demo sizes collateral from the mocked price** — `Demo._borrowerRequest` · seen in 1/2 runs · NEW — The demo computes collateral from the simulation price, so the live check can reject the request if the price moved.
- **Deploy logs an unreadable oracle and continues** — `Deploy.run` · seen in 2/2 runs · NEW — The post-deploy check only logs `tryGetPrice`, and on testnet it reads the simulation mock, so a broken feed ships without a stop.
- **Deploy grants no KEEPER_ROLE** — `Deploy.run` · seen in 1/2 runs · NEW — Only the loan lender can liquidate, because the script never grants `KEEPER_ROLE`.
- **The liquidation ratio floors before it scales** — `LiquidationEngine._cr` · seen in 2/2 runs · NEW — The same two-floor ratio lets a lender liquidate a loan whose exact ratio is a fraction of a basis point above 120 percent.
- **health returns crBps 0 when the price is unusable** — `LiquidationEngine.health` · seen in 1/2 runs · NEW — A keeper that compares `crBps` to the threshold reads every loan as undercollateralized while the feed is stale. Off-chain impact only.
- **The lender can wait so accrued interest takes more collateral** — `LiquidationEngine.liquidate` · seen in 2/2 runs · NEW — Debt is read at call time and interest keeps accruing, so a lender who waits seizes more BTC. The borrower owes this interest by the loan terms.
- **A loan is liquidatable in the first block below 120 percent** — `LiquidationEngine.liquidate` · seen in 2/2 runs · NEW — No grace applies below the threshold and no top-up path exists, so the borrower can cure only by a repay.
- **The lender picks the block, and so the price, of an overdue liquidation** — `LiquidationEngine.liquidate` · seen in 2/2 runs · NEW — Only the lender or a keeper calls `liquidate`, so the lender chooses the price that sizes the BTC claim. The USD claim does not change.
- **A pause does not stop liquidation** — `LiquidationEngine.liquidate` · seen in 1/2 runs · NEW — `liquidate` has no pause check, so a lender can liquidate while the protocol is paused. The interface keeps liquidation open on purpose.
- **A stale feed blocks every liquidation** — `LiquidationEngine.liquidate` · seen in 2/2 runs · NEW — `liquidate` reads the price before the reason check, so a feed outage blocks overdue liquidations too. Documented trade-off; feed heartbeat not verified.
- **previewLiquidation returns a split for a closed loan** — `LiquidationEngine.previewLiquidation` · seen in 2/2 runs · NEW — The function does not check the loan status, so a UI reads the full stored collateral as the borrower share of a closed loan.
- **Repaying the owed() amount leaves dust principal** — `LoanManager.repay` · seen in 1/2 runs · NEW — Interest accrues between the read and the call, so a borrower who sends the exact `owed()` value keeps a dust balance and a locked loan. Front ends pass max.
- **A late repay can lose a block-ordering race to liquidation** — `LoanManager.repay` · seen in 2/2 runs · NEW — After grace both `repay` and `liquidate` pass the status check, so block order decides the outcome.
- **A token halt blocks repay but not liquidation** — `LoanManager.repay` · seen in 2/2 runs · NEW — `repay` moves MUSD and `liquidate` does not, so a halted token stops the cure but not the seizure. MUSD halt policy not verified.
- **Liquidation credits no interest to the lender tally** — `LoanManager.settleLiquidation` · seen in 1/2 runs · NEW — `repay` adds to `interestEarned` and `settleLiquidation` does not, so the on-chain interest tally undercounts liquidated loans.
- **borrowFromOffer can leave offer dust below minLoan** — `LoanMarketplace.borrowFromOffer` · seen in 1/2 runs · NEW — A borrower can take an amount that leaves a remainder below `minLoan`, so only an exact fill or a cancel clears it.
- **_cr overflows for an extreme price** — `LoanMarketplace._cr` · seen in 1/2 runs · NEW — `collateral * price` overflows above a price near 1.16e58, so every CR check reverts. No realistic feed reaches it.
- **A lender can split one request into many small loans** — `LoanMarketplace.fundRequest` · seen in 1/2 runs · NEW — Each `fundRequest` call opens a separate loan, so a lender can make the borrower repay many minimum-size loans.
- **A loan can open on a price up to one hour old** — `LoanMarketplace.matchOfferAndRequest` · seen in 2/2 runs · NEW — The CR check accepts any price younger than `maxStaleness`, so a loan can open below the ratio at the live price. Feed lag not measured.
- **maxBorrow can return amounts that createRequest rejects** — `LoanMarketplace.maxBorrow` · seen in 2/2 runs · NEW — The view ignores `maxLoan`, the collateral cap and the minimum ratio, so a UI can show a size that reverts.
- **minCollateral can quote collateral above the per-loan cap** — `LoanMarketplace.minCollateral` · seen in 1/2 runs · NEW — The view does not apply `maxCollateralPerLoan`, so a large amount gets a quote that `createRequest` rejects.
- **A completing fill can open a loan below minLoan** — `LoanMarketplace._takeFromRequest` · seen in 1/2 runs · NEW — A fill that leaves a tiny remainder lets the next completing fill open a loan under the minimum size.
